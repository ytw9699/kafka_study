## 배경

실험 B(워커 종료)를 다시 돌리다 화면 표시가 틀린 것을 발견했다.

**1. 정상 종료한 워커가 "놀고 있음"으로 보였다.**

정상 종료하면 워커는 `onPartitionsRevoked` 에서 파티션을 반납하며 DB 를 마지막으로 한 번 갱신한다.
화면은 "마지막 하트비트가 8초 이내면 살아 있음"으로 판단하므로, 종료 직후 8초 동안은
**"살아 있는데 파티션이 없는 워커" = 놀고 있음**으로 표시됐다. 8초 뒤에는 "죽음"으로 바뀌어,
정상 종료와 `kill -9` 가 화면에서 구분되지 않았다.

정상 종료와 강제 종료의 차이(스스로 반납 vs 하트비트가 끊길 때까지 기다림)는 실험 B 의 핵심인데, 화면이 그것을 가리고 있었다.

**2. 화면 안내문이 부정확했다.** "`kill` 로 종료하면 `onPartitionsRevoked` 가 불리지 않는다"고 적혀 있었다.
`kill`(SIGTERM)은 정상 종료라 불린다. 불리지 않는 것은 `kill -9` 다.

**3. Kafka UI 이미지가 `latest` 였다.** 나중에 클론하는 사람마다 다른 버전을 받게 된다.

## 작업 내용

## 배운 것

- **"살아 있다"와 "일하고 있다"와 "스스로 떠났다"는 서로 다른 상태다.** 하트비트 하나로는 앞의 둘만 구분된다.
  스스로 떠났다는 것은 떠나는 쪽이 **알려 줘야만** 안다 — Kafka 의 `LeaveGroup` 요청이 정상 종료를 빠르게 만드는 이유와 같다.
- **관찰 도구가 틀리면 실험이 틀린다.** 실험 B 의 결과(3초 vs 42초)는 맞았지만, 화면은 그 차이를 만든 원인을 보여주지 못하고 있었다.
