## 배운 것

- **결과는 한 문서에 쓰고 끝나지 않는다.** 7단계를 마치고 README 와 티켓은 고쳤지만, "예정"이라고 적어 둔 문서 다섯 곳이 그대로 남았다.
  "아직 안 했다"고 적은 곳은 **나중에 반드시 틀린 말이 된다.** 미래형 문장은 작업이 끝날 때 함께 찾아 고쳐야 한다 — `grep "예정\|7단계에서\|미착수"` 가 가장 빠른 점검이었다.
- **이름이 겹치면 링크가 오히려 혼란을 준다.** README 안에서는 "실험 D"가 자연스러웠지만, 링크를 따라가면 다른 문서에서 실험 D 는 전혀 다른 실험이었다. 문서끼리 이어 읽히는 순간 이름은 전체에서 하나여야 한다.
- **정정은 아래에 덧붙이는 것보다 원문을 고치는 것이 낫다.** KS-20 은 정정 박스가 있었지만, 위에서부터 읽는 사람은 틀린 문장을 먼저, 그것도 굵게 읽는다.
