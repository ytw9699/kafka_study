## 배경

README 의 구조 그림은 4절에 있는 글자 그림이었다. 화면 · 중계 그룹 · DB 가 빠져 있었고,
처음 보는 사람이 README 를 한참 내려야 전체 모양을 볼 수 있었다.

## 작업 내용

- [x] "30초 요약" 바로 아래에 mermaid 그림 "한눈에 보는 전체 구조" 추가
- [x] 그림의 ①~⑥ 번호마다 무슨 일이 일어나는지 표로 설명
- [x] 4절의 글자 그림은 빼고 위 그림을 가리키게 정리

## 그림을 그리며 고른 것

| 시도 | 결과 | 판단 |
|---|---|---|
| 왼쪽 → 오른쪽 배치, 화살표마다 설명 | 같은 설명이 화살표마다 반복되고 선이 꼬였다 | 탈락 |
| 위 → 아래 배치, 화면으로 돌아가는 화살표 | 화살표가 위로 거슬러 올라가며 배치가 뒤틀렸다 | 탈락 |
| **브라우저를 "입력"(위)과 "화면"(아래)으로 나눔** | 모든 흐름이 위에서 아래로만 흐른다 | **채택** |

## 검증

- mermaid 10.9.1 로 실제 렌더링해 선이 꼬이지 않는 것을 확인
- README 안의 `#한눈에-보는-전체-구조` 앵커 확인

## 배운 것

- **그림이 꼬이는 원인은 대부분 "거꾸로 가는 화살표"다.** 같은 대상을 두 번 그리는 한이 있더라도 흐름을 한 방향으로 만들면 읽는 사람이 따라가기 쉽다.
- **점선 하나가 Kafka 와 큐의 차이를 보여준다.** 같은 파티션에서 실선(잔액 계산)과 점선(중계 · 부정탐지)이 동시에 나가는 모습이 "읽어도 지워지지 않는다"를 설명 없이 보여준다.
