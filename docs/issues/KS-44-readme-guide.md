## 배경

이 저장소는 **처음 보는 사람이 짧은 시간 안에** 읽게 된다. 그 관점에서 README 를 다시 보니 두 가지가 없었다.

| 없던 것 | 왜 문제인가 |
|---|---|
| 바쁜 사람이 어디부터 볼지 | 읽는 순서 안내가 8절(한참 아래)에야 있었다 |
| 코드 위치 | 문서는 안내하는데, 핵심 동작이 **어느 파일에** 있는지는 알려 주지 않았다 |

## 작업 내용

- [x] 맨 위 기간 표 아래에 **"바쁘시면 — 5분 코스"** — 프로그램 소개 · 실제 화면 → 확인한 결과 → KS-20, 코드 지도 링크

## 검증

- README 안의 상대 링크 · 앵커 검사 — 깨진 것 0건
- 코드 지도의 함수 이름(`publish` · `consume` · `apply` · `seekToBeginning` · `markStopped` · `relay` · `expectedBalances` · `missedPartitions` 등)이 실제 코드에 있는지 확인

## 배운 것

- **문서 지도와 코드 지도는 다르다.** 문서를 아무리 잘 정리해도 "그래서 코드는 어디 있나"에 답하지 못하면, 읽는 사람은 폴더를 직접 뒤진다.
