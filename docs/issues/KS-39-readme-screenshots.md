## 어떻게 찍었나

브라우저 창 캡처는 크기가 줄어들고 일부만 찍혀서, 설치된 Chrome 을 `puppeteer-core` 로 띄워
**패널(section) 단위로** 찍었다. 실험 조작은 README 절차와 같은 API 호출로 했다.

- 장면 A · B: 데이터 초기화 → 워커 3개 → 연속 거래 → 키 RANDOM → 연속 거래 2번 → 워커 하나 정상 종료, 하나 `kill -9`
- 장면 C · E: 데이터 초기화 → 워커 1개 → 연속 거래 → replay → rebuild → 영구 실패 거래

찍은 스크립트는 레포에 넣지 않았다. 화면을 다시 찍을 일은 드물고, 학습 대상이 아니라서다.

## 찍으면서 발견한 것

replay 직후 잔액표 아래에 **"화면을 켜기 전에 발행된 거래가 있어 기대 잔액이 부족하게 계산됩니다"** 경고가 떴다.
이번에는 화면을 먼저 켰으므로 **틀린 경고**다.

화면은 "워커가 적용한 건수 > 화면이 받은 거래 수"이면 이 경고를 띄우는데, replay 로 **같은 거래를 두 번 적용한 경우**를 구분하지 못한다.
README 에 오해를 주는 문구가 실리지 않도록 이 사진은 버튼까지만 찍었다. 경고 판정 자체는 고치지 않았다 — 후속 과제.

## 배운 것

- **결과는 매번 조금씩 다르다.** 실험 A 는 기록(KS-20)에서는 5명이 어긋났지만 이번에는 4명이었다. 사진은 찍힌 그대로 두고, README 에 "실행할 때마다 조금씩 다르다"고 적었다.
  분산 시스템의 순서 버그가 재현하기 어렵다는 것 자체가 학습 포인트다.
- **화면의 보조 판정도 검증 대상이다.** 스크린샷을 꼼꼼히 보다가 경고 문구가 틀린 상황에서도 뜬다는 것을 찾았다.
